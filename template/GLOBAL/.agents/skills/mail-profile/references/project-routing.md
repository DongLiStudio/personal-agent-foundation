# 邮箱 Profile 的项目路由

## 放置规则

- `GLOBAL/MAIL_PROFILES.md`：用户控制且需要跨项目长期使用的邮箱逻辑身份和非敏感路由。
- 项目 `AGENTS.md`：项目默认邮箱 Profile、身份类型和不可跨主体边界。
- 项目 `docs/...`：客户例外、特定业务邮箱和资源路由。
- Provider/OAuth/系统凭据存储：密码、授权码、token和动态认证状态。

## 解析顺序

1. 用户当前请求明确指定的邮箱、公司或个人身份。
2. 项目中与当前业务主体直接匹配的条件化路由。
3. 项目默认邮箱 Profile。
4. GLOBAL 默认邮箱 Profile。

同级规则冲突、项目没有声明且GLOBAL也无默认、或邮件内容可能属于其他主体时，在读取前询问。不得以当前客户端登录账号补齐缺失路由。

## 项目业务边界

邮箱 Skill 负责身份和读取；业务项目负责附件的用途判断与后续写入。例如发票进入账目或审批系统前，必须继续按对应项目的财务与审批规则处理，并固定使用该项目已确认的身份路由。
