# 验收与迁移恢复

## 验收记录

仅存非敏感摘要到目标项目：

| 范围 | 最小证据 |
| --- | --- |
| 接入 | ALLinSSL 版本、实例路由、只读 API 成功、时间 |
| 授权 | DNS/SSH/report ID 与对应项目范围，SSH 主体及公开公钥指纹；无配置正文 |
| DNS | 每域名预期记录、解析和外部观察；旧值保留用于回退 |
| 申请 | CA、SAN、实际有效期、公开证书指纹，申请失败双渠道覆盖 |
| 部署 | 每目标路径、权限、证书/key匹配、配置验证、reload 与实际对外指纹 |
| 调度 | active、周期、时区、续期阈值、ARI 兼容性 |
| 通知 | 两个来源ID、失败覆盖、独立尝试机制、配置和真实送达分别记录 |
| 监控 | 每域名两个来源覆盖、周期、阈值、首次检测、检测器运行环境 |
| 应用 | HTTPS；按服务要求另验 WSS、登录、上传/终端等业务 |
| 交付 | 完成项、阻塞、未验边界、回退方法、commit/push 状态 |

不能把 HTTP 200 当作证书有效证明；不能把一次正常手动签发当作未来自动续期已验证。自然到期续期需后续观测，不提前伪称已经发生。健康 HTTPS 只证明端点与证书监控，不等于应用健康监控。

通知源不足或消息测试未授权时，写明状态并要求缺少的信息/授权，继续不依赖它的工作；已有服务不擅自停用。用户明确选择低于默认保障时记录例外，不反复询问。

## 恢复与迁移顺序

1. 从 GLOBAL 源稿恢复 Skill 与依赖；重新读取项目、服务器路由、官方版本资料。安装能力不携带旧机器凭据。
2. 通过独立安全渠道恢复 API Key、DNS 凭据、SSH 私钥、通知渠道授权；禁止复制到 GLOBAL/Git。若迁移 ALLinSSL 数据，需单独获得受限库/Secret 备份迁移授权，本 Skill 的单项 API Key 读取授权不等于整库权限。
3. 核验新宿主操作系统、架构、版本、时区、网络、权限及持久化。容器化不保证 x86/ARM 镜像、文件路径、socket 或 SSH 行为相同。
4. 先恢复只读 API 和凭据验证，再查唯一对象与引用关系；不要按旧显示名称重复创建授权。ID 换实例可能不同，显式映射引用并验收。
5. 在新入口准备 TLS 服务与证书，在 DNS 切换前用指定目标 IP + 正确 SNI/Host 验证。更换业务服务器时记录旧入口与解析；更换 ALLinSSL 时避免新旧两套调度同时签发。
6. 验证部署、失败双渠道、所有域名监控首次检测与业务入口，再按授权切换解析和自动调度。按 TTL 观察公网，保持受限回退材料。
7. 完成观察与回退验证后，只有获得清理授权才移除旧公钥、旧节点、旧通知引用或旧实例；不能按注释或应用名删除密钥。
