# ALLinSSL 证书自动化

## 工作起点与依赖

读取当前项目 AGENTS.md、README.md、STATUS.md 和声明的 GLOBAL 入口。项目存放域名、目标服务、授权引用与验收记录；全局 Skill 只维护通用流程。

先定位长期使用的 ALLinSSL 控制中心：

1. 读取 GLOBAL 服务器索引和当前项目明确路由的服务器详情。没有已登记服务器时，先与用户协商长期宿主并按 `server-profile` 完成接入；不得自行选购、接入或部署服务器。
2. 有已登记服务器时，先根据服务索引找出部署了 ALLinSSL 的候选服务器，再仅对项目相关候选执行最小只读在线核验；不扫描无关服务器。
3. 发现一个合适实例时，核验版本、持久化与备份、长期在线性、API 接入、通知能力以及到 DNS 和部署目标的网络可达性，满足要求就复用。
4. 发现多个实例时，依据项目现有引用、稳定性和权限边界选定唯一主实例；不得为本次任务自动新建另一个控制中心。
5. 未发现实例或现有实例不适合长期使用时，整理候选宿主、部署方式、持久化、备份和网络影响，与用户确认长期宿主及部署授权；确认前不安装 ALLinSSL。

先确认已有授权，继续用户已允许的部署与配置工作，不重复询问已有决定。发现缺少必要信息或权限时尽早询问，同时完成独立的准备工作。Skill 本身不授权云资源变更、安装服务、重启、修改其他项目或发送消息。

按范围调用已安装的 server-profile、tencentcloud-profile、aliyun-profile；宿主没有这些 Skill 时按项目规则完成同样的身份和指纹核验，不假定工具已存在。腾讯云/DNSPod 是适配方案，不是强制依赖；DNS 权限与云主机权限分别核验。

操作 API 时读 [安全接入与 API](references/api-safety.md)；涉及服务端、DNS 或部署时读 [部署与失败保障](references/deployment.md)；验收或迁移时读 [验收与恢复](references/acceptance-recovery.md)。

## 最小输入与缺项处理

| 输入 | 必须确认的事实 | 缺失时 |
| --- | --- | --- |
| ALLinSSL 接入 | 已登记服务器、现有实例位置、版本、宿主/容器、API Key 可用性及允许的安全读取方式 | 先发现并复用合适实例；没有合适实例时与用户确认长期宿主和部署授权，再完成安全 API 接入；不得索要聊天明文密钥 |
| 域名与 DNS | 所有对外域名、DNS 托管方、真实账号主体、zone 权限、记录现状与目标地址 | 引导授权；授权不能替代域名列表查询 |
| 部署目标 | 唯一服务器 Profile、可信指纹、SSH 主体、实际 TLS 入口与证书路径 | 补齐连接；按本次部署授权准备入口 |
| 通知源 | 至少两个不同的可用 report/channel ID，接收方与项目范围明确 | 要求用户提供或授权配置缺少的来源 |
| 业务入口 | 服务后端、公开范围、端口、HTTP/WSS 等功能及回退方法 | 不猜测或覆盖既有站点 |

已有通知源先核验，只有用户授权本项目复用后才接入；不因名称带其他项目而一律阻止用户明确指定的复用，也不自行跨租户复用。优先选择不同传输渠道（例如飞书与邮件），两个节点引用同一个渠道不算两个来源。

缺少两个来源时不能宣称完整上线、不能新启用无人值守流程；已运行的流程不得因此擅自停用，报告缺口并继续其余授权工作。

## 默认策略

这是用户确定的工作流默认值；用户当前明确指令或项目显式覆盖优先，覆盖项写入项目记录。双来源要求除非用户明确决定例外，否则保持。

| 项目 | 默认值 |
| --- | --- |
| CA | Let's Encrypt；标识和 ACME 端点以目标版本为准 |
| 续期 | 剩余有效期不足 30 天进入续期；正确设置目标版本的 end_day 字段与边界语义 |
| 调度 | 每日检查一次，选择不拥挤的时段并明确时区 |
| ARI | 版本支持时启用；核查与 30 天阈值的实际交互，不假定固定时点必签发 |
| 密钥算法 | RSA2048；按入口兼容性和项目要求选择 ECDSA |
| DNS 验证 | DNS-01，使用受限域名/zone 权限 |
| SSH | 每服务器独立的 ALLinSSL 专用密钥，优先受限部署用户 |
| 失败通知 | 至少两个来源，覆盖申请和每个部署目标的失败 |
| HTTPS 证书监控 | 每个对外域名覆盖至少两个来源；5 分钟检查、提前 25 天提醒、重复间隔 10 分钟 |

证书的实际有效期由 CA 决定，不写死为 90 天。记录到期时间同时标注时区。同张 SAN 证书覆盖多个域名，不能替代逐域名对外监控。

## 执行闭环

1. 按上述服务器优先顺序定位并选定 ALLinSSL 控制中心；随后只读发现其 API、DNS、目标入口和通知配置，构建无凭据的项目计划。按唯一对象 ID 查重，并记录旧解析、站点配置、引用关系与可回退状态。
2. 安全建立 API 接入，补齐 DNS 与 SSH 授权；给 SSH 授权按稳定服务器 Profile 命名，不按当前应用命名。改名/认证切换保留原 ID 和其他引用。
3. 准备实际 TLS 入口。Nginx 方案先检查或安装 Nginx、规划站点与证书路径、检查权限和端口；已有其他入口时使用对应适配器，不为证书强制安装第二套 Nginx。
4. 按授权创建或修改 DNS，核实公网解析和入口可达性。DNS-01 的 TXT 验证和业务 A/AAAA/CNAME 解析是两项独立工作。
5. 配置证书、各部署节点以及双来源失败保障，校验节点 ID、inputs/fromNodeId 和失败可达路径。每个通知独立尝试；第一个通知失败不得阻止第二个。
6. 为所有对外域名配置双来源监控。若版本每条仅支持一种报告类型，则每域名建两条；若支持多渠道，则验证实际展开覆盖而非只计算条数。
7. 新流程先禁用调度，完成手动执行、部署与外部验收后启用；已有流程做最小修改。验证双渠道真实送达需要测试通知授权；已有明确授权则执行，未经授权不主动发消息、不破坏生产制造失败。
8. 回读自动调度、所有监控首次检测和引用关系，记录状态及缺口。配置已完成、送达已验证、部署验收、迁移验收分别报告。

失败时先确认当前副作用，禁止盲目重建对象或重复签发；关注 CA 限流。一次不确定写入先按 ID 回读，最多两次有新证据的重试，然后停止该写路径并报告。审批拒绝不得绕过。

## 完成定义

完整上线要求接入可用、DNS 正确、部署成功并加载有效证书、申请/部署失败各有双来源保障、每域名双来源监控已启用且首次检测通过。未测试通知送达须明确标记，不能用节点存在代替送达验收。API 不可用或版本不能表达可靠失败路径时报告阻塞，不改写 SQLite 业务表作为捷径。

只改名称或认证方式时按该项范围验收，不为满足完整上线定义重做或扩大其他服务变更。换宿主后重新核验能力与版本；此前一个环境的成功不等于跨平台迁移已经验证。
