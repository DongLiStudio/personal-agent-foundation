# 服务器连接

## 路由与边界

读取当前项目 AGENTS.md、README.md、STATUS.md，以及上层 GLOBAL 的 README.md、GLOBAL_CONTEXT.md、SERVER_PROFILES.md。已有 Profile 只读取对应 servers/<profile>.md；新服务器确认地址、端口、用户和用途，不推断默认主机或 root 权限。

连接授权不等于部署、重启或安全策略变更授权。不得输出私钥、密码、完整环境变量或未经筛选的日志。首次公钥安装需要可信控制台或已验证连接；没有初始权限时提供一条可复制命令，不伪称已连接。

## 首次接入与轮换

1. 检查别名、密钥路径是否已存在，不覆盖旧密钥。私钥只保存在用户 SSH 安全目录；确认文件 ACL/权限仅授权用户及必要系统主体可读。
2. 自动化连接采用用户认可的免交互方式。新建空口令密钥时，通过 Python subprocess 参数数组传递空字符串，禁止依赖 Windows shell 的空引号传递。示例：subprocess.run(['ssh-keygen','-t','ed25519','-f',key_path,'-N','','-C',profile],check=True)。运行前确认私钥和 .pub 路径均不存在。
3. 在让用户安装公钥之前，执行 ssh-keygen -y -P 空字符串 -f 私钥（同样通过参数数组），捕获输出并比较其前两个字段与 .pub 一致；验证失败立即停止，不分发公钥。已有加密私钥不能猜口令或改为无口令；引导用户安全解锁或授权创建不同文件名的新密钥。
4. 从用户云控制台获取主机公钥指纹。ssh-keyscan 只用于取得候选公钥，不是信任来源。候选指纹必须与可信来源一致；与另一台已登记服务器指纹相同也需核查是否操作错主机或克隆密钥。不能关闭 StrictHostKeyChecking 或直接信任未知密钥。
5. 用户控制台追加公钥时使用单行 grep -qxF 公钥 authorized_keys || echo 公钥 >> authorized_keys，确保目录 700、文件 600 且属主正确；不覆盖原授权。公钥仅使用已生成并核验的完整值，不包含占位符。无需重启 sshd。
6. 先用显式地址、身份文件、已验证 known_hosts、BatchMode=yes 和 IdentitiesOnly=yes 测试 whoami、hostname；再局部追加或更新别名，设 StrictHostKeyChecking=yes，独立重连验收。保留其他 Host 配置；用 ssh -G 核对最终生效路由。
7. 轮换时只有新连接成功且用户授权清理后，按完整公钥字段精确移除旧授权，逐字节验证其他行不变，再重连。不要仅按注释删除；不要顺便删除本机旧私钥。
8. 登记 GLOBAL 索引及详情前，完整读取 [服务器详情模板](references/profile-template.md)，并与 GLOBAL 中一份现行服务器详情横向核对结构。按模板登记，不写成临时流水账；不复制参考服务器的账号、权限或服务事实。私钥和口令不进入 Git。未成功连接必须明确标注待验收。

## 登记验收

- 详情必须包含“定位与连接”“权限与安全边界”“服务索引”“恢复说明”，服务表采用模板六列；未知字段标记待核验，不推断。
- 索引别名、详情标题、SSH config 最终路由和身份文件必须一致；客户端公钥与服务器主机指纹分开记录，禁止混用。
- 将长期事实与带日期的运行快照分开；未检查服务时不编造清单，旧的“待盘点”说明在实际盘点后更新。自启动配置存在不等于重启验收通过。
- 写入后回读完整详情，逐项对照模板与本次证据；检查 Markdown 链接、敏感信息及 diff。Skill 语法校验不能替代输出文档验收。

## 诊断顺序

- 别名不能解析：核对当前 HOME、SSH config 和沙箱权限，不判断为服务器宕机。审批拒绝不得绕过。
- Permission denied：先测试私钥空口令解锁（仅对声明免口令的新密钥），检查公私钥匹配，再读取过滤后的 ssh -vvv 输出。缺少可选 -cert 文件或 ssh-agent 不等于根因。
- Offering public key 是提交候选；Server accepts key 只是接受候选，不等于签名或认证完成；只有实际远程命令成功才算通过。
- 本地签名能力验证后，再核对服务端 namei 权限、sshd -T -C 的实际 Match 配置及对应时间/IP日志。不要盲目放宽 PermitRootLogin、算法或文件权限。
- 同一错误最多两次无新证据重试，之后更换诊断层；避免让用户反复执行无变化命令。

## 完成与恢复

报告连接验证、误加授权清理、配置和登记状态，分清 SSH 可用与业务健康。换机从安全渠道恢复私钥，重新核验指纹，不从 GLOBAL 恢复秘密。Skill 源稿、安装副本和依赖清单按 record-skill-dependency 保持一致。
