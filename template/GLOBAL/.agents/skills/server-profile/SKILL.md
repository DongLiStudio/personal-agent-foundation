# 服务器连接

## 路由与边界

读取当前项目 AGENTS.md、README.md、STATUS.md，以及上层 GLOBAL 的 README.md、GLOBAL_CONTEXT.md、SERVER_PROFILES.md。已有 Profile 只读取对应 servers/<profile>.md；新服务器确认地址、端口、用户和用途，不推断默认主机或 root 权限。

连接授权不等于部署、重启或安全策略变更授权。不得输出私钥、密码、完整环境变量或未经筛选的日志。首次公钥安装需要可信控制台或已验证连接；没有初始权限时提供一条可复制命令，不伪称已连接。

## 会话复用

同一任务对同一服务器、同一主体的连续操作复用一个持续 SSH 会话，完成后立即退出，避免每条命令重新申请 Bitwarden 签名。首次独立认证和密钥轮换验收仍使用新连接；目标/主体变化或连接断开时重新认证。保持始终提示授权、主机校验和 `ForwardAgent no`，不建立跨任务常驻连接。已认证会话可继续执行命令，锁定 Bitwarden 不会断开它；进程名称只用于辨认，不作为防仿冒依据。详细边界见 [Agent 接入与验收](references/agent-access.md)。

## 首次接入与轮换

1. 人工 SSH 默认在 Bitwarden 桌面端创建独立 Ed25519 SSH 密钥条目，启用 SSH Agent 并设置每次签名提示授权；不默认在磁盘生成、导出或恢复私钥。没有桌面端时先引导安装、启用和验证；`bw` CLI 不代替桌面 SSH Agent。
2. 完整读取 [Agent 接入与验收](references/agent-access.md)，按实际 Windows/macOS 客户端和安装来源检查通道、socket 及公开指纹。Bitwarden 已开启不代表 Git、WindTerm 等全部接入；每种实际客户端单独验收。用户指定 root 时据实保留主体，不擅自另创用户。
3. 核验用户提供公钥的算法、完整编码和指纹，服务端只安装公钥。若用户仍坚持文件私钥，先解释泄露风险并再次确认具体例外，优先加密口令与最小 ACL；不能因 Agent 拒签而自动生成无口令私钥。现有业务专用凭据遵循对应服务规则，不顺带撤销。
4. 从用户云控制台获取主机公钥指纹。ssh-keyscan 只用于取得候选公钥，不是信任来源。候选指纹必须与可信来源一致；与另一台已登记服务器指纹相同也需核查是否操作错主机或克隆密钥。不能关闭 StrictHostKeyChecking 或直接信任未知密钥。
5. 用户控制台追加公钥时使用单行 grep -qxF 公钥 authorized_keys || echo 公钥 >> authorized_keys，确保目录 700、文件 600 且属主正确；不覆盖原授权。公钥仅使用已生成并核验的完整值，不包含占位符。无需重启 sshd。
6. 先用显式地址、端口、主体和已验证 known_hosts 建立新的 Agent 连接，验收时禁用文件身份、密码/交互回退及连接复用，执行 whoami、hostname；观察目标条目签名授权与最终认证。再按需维护公开别名、保留其他 Host，并用 ssh -G 核对路由。正常使用同时提供完整 IP/域名命令，不要求换机先有别名。不默认转发 Agent。
7. 轮换时只有新连接成功且用户授权清理后，按完整公钥字段精确移除旧授权，逐字节验证其他行不变，再重连。不要仅按注释删除；不要顺便删除本机旧私钥。
8. 关闭密码需独立授权：先核验恢复入口、有效 Include/Match 与账号条件，语法通过再 reload，新公钥连接和密码/交互负向测试分别验收。公钥成功不代表全机密码已关闭。登记前完整读取 [服务器详情模板](references/profile-template.md)，横向核对一份现行详情，不复制其事实。私钥和口令不进入 Git，未验收字段明确待核验。

## 登记验收

- 详情必须包含“定位与连接”“权限与安全边界”“服务索引”“恢复说明”，服务表采用模板六列；未知字段标记待核验，不推断。
- 索引、详情、实际地址/端口/主体与 Agent 公钥身份必须一致；客户端公钥与服务器主机指纹分开记录，禁止混用。公钥选择器是公开路由，不强制永久保存，不能从服务器主机公钥推导客户端身份。
- 将长期事实与带日期的运行快照分开；未检查服务时不编造清单，旧的“待盘点”说明在实际盘点后更新。自启动配置存在不等于重启验收通过。
- 现行详情不累积变更日志：移除已撤销人工指纹、被替代状态和重复验收流水，历史交给 Git 与项目记录；保留现行自动化授权、必要回退入口和未解决风险。只删除文档噪声，不因此删除实际密钥、备份或账号。
- 写入后回读完整详情，逐项对照模板与本次证据；检查 Markdown 链接、敏感信息及 diff。Skill 语法校验不能替代输出文档验收。

## 诊断顺序

- 别名不能解析：核对当前 HOME、SSH config 和沙箱权限，不判断为服务器宕机。审批拒绝不得绕过。
- Permission denied：先检查 Agent 通道、目标公开指纹和签名授权，再读取过滤的调试输出。agent refused operation 优先检查锁定、拒绝/超时，不放宽服务端或导出私钥。
- Too many authentication failures：检查 Agent 候选数量/顺序是否耗尽 MaxAuthTries；可按需用公开公钥选择器。调整服务端上限必须明确授权并检查实际生效范围，不能默认批量加大。
- Offering public key 是提交候选；Server accepts key 只是接受候选，不等于签名或认证完成；只有实际远程命令成功才算通过。
- 本地签名能力验证后，再核对服务端 namei 权限、sshd -T -C 的实际 Match 配置及对应时间/IP日志。不要盲目放宽 PermitRootLogin、算法或文件权限。
- 同一错误最多两次无新证据重试，之后更换诊断层；避免让用户反复执行无变化命令。

## 完成与恢复

报告连接验证、授权清理、配置和登记状态，分清 SSH 可用与业务健康。换机安装并解锁 Bitwarden、启用 Agent、重建公开路由及主机信任，不默认导出私钥。Agent 降低可复制文件和无提示签名风险，不保证对木马、已授权会话劫持或误批准绝对安全。Skill 源稿、安装副本和依赖清单按 record-skill-dependency 保持一致。
