## 公式测试矩阵

在合同授权的隔离环境/测试记录执行，使用可识别测试标记，登记精确record ID，避免正式成绩、通知和自动化被测试污染。清理仅限已授权且确认为本轮测试的记录；默认保留证据，不擅删生产记录。

- 全对、全错、已提交空答（按规则）、未提交。
- 单选每个选项至少命中一次；多选所有组合（四选项16种）、顺序变化、少选、漏一个/多一个、全选和空集。
- 填空已接受等价项、相近错误词、大小写/空格策略边界；动态题不当成自动固定答案。
- 实操/人工分未评、真实0、满分、负数、超满分、小数；无效分必须拒绝。
- 多评委缺一个、同角色重复、跨岗位、跨版本、同人多答卷；不允许“计算有值就完成”。
- 权重各端点与混合样本、最终满分、附加分上限、舍入边界、上游变化对下游的真实传播。

`exam_guard.py` 用于已支持题型的独立数学与映射校验。多评委聚合、跨表公式、UI/权限不在脚本覆盖内，须按该次合同补充可重复测试和真实回读。快照由真实接口/UI归一化，不把期望 manifest 复制成“实际快照”。

## 交付内容

1. 考试全名/版本、知识库完整路径、试卷/评分表/答题入口/考场群/受限管理入口。
2. 采用/排除材料与覆盖统计、题型题数、各级满分、通过规则是否已确认。
3. 表单设置证据、权限矩阵、公式测试结果与差异（零差异才写零）。
4. 考生加入、领卷、按阶段提交、看结果、退出考场的教学；管理员如何验证撤权。
5. 含实操时：专属 Skill 的确切路径/名称、何时运行、完整可复制调用、输入身份、报告位置、复阅和分歧处理。
6. 尚未完成的人工项/平台限制、阻塞影响、具体责任动作。未完成必需项时明确“不具备正式开考条件”。

在所确认考试目录写入或更新一份使用说明，避免多份同名手册；是否提供下载ZIP按分发需求，分发包不得含真实答案、考生数据或凭据给无权接收者。项目保留版本化 manifest、资源映射、验收记录；临时请求payload不作为正式成果。

## Skill 自身交接给另一位使用者

给出可复制启动语：“使用 $feishu-exam-builder，为……制作考试；先引导我确认考试材料、题型与评分规则，以及资产工程内的精确位置，确认后完整实施并教学。”

第一轮外部验收应覆盖一个含单选、多选、填空、实操的混合卷，以及多人评委模式；先协商隔离测试位置与账号。让新使用者仅凭 Skill 和资料完成，不提供作者的隐含历史上下文。按上述门禁记录真实完成情况，发现缺陷后修订通用流程，不把一次业务特例硬编码为全球规则。
