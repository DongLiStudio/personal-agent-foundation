# 需求与归档合同

## 渐进询问

先从用户信息、项目规则、实时资源提取已知项，按下列顺序只问缺少且会改变结果的内容；每轮合并 1—3 个问题，不一次抛出空白长表。

1. **目的与范围**：考试名称/版本、对象、要验证的能力、依据材料/链接、排除范围；新建、改版还是复用现有考试？题库是否全量考或抽题，题型与题量、难度、考试时长/开闭卷及工具规则由用户决定，不能从历史卷复制。
2. **归属与组织**：所属项目和飞书主体、资产工程知识空间、父目录候选、管理员/通知接收人、考生与评委/带教角色。未给考生名单可先建空考场，不自行拉入真实人员；只授予组织者已确认的权限。
3. **计分与交付**：各模块原始满分与最终贡献、附加分上限、通过标准是否已确定、评分人结构、结果可见范围、当前成绩生成与提交后路径；含实操时确认允许工具、固定材料和可核验成果。

以下是本 Skill 默认值，作为确认单的一组列出，不反复询问：至少两表；考生一页一题；每位考生每天一次；群名称 `[权限] - 考场 - {考试名称}`；其余表单开关见表单规范。用户明确覆盖时保留新值及其影响。历史制度的题量、权重、人名、表 ID、权限组不是全局默认。

## 来源盘点

- 递归列全用户指定知识库子树，处理分页至 `has_more=false`；读取根正文、每个子文档及其中直接用于出题的链接与附件。快捷方式解析原节点，按实际对象 ID 去重并防循环。空节点和不可访问项也计入清单，不以标题代替阅读。
- 用表记录 `source_id / URL或路径 / 标题 / 当前版本或revision / 读取时间 / 适用对象 / 生效状态 / 可访问 / 采用或排除原因 / 对应题号`。对材料改版不明、相互矛盾、仅口头提案和缺权限处暂停相关命题。
- 用户要求参考历史会话时，先检索项目相关任务与归档，再读全部命中会话中的相关轮次、用户修正与失败结果。分清原话、助手结论、压缩摘要、缺失轮次。无法恢复的内容列边界，不宣称“全历史无遗漏”。
- 考生无权阅读的内部参考不得直接变成学习前提；必要时生成经批准的脱敏考试材料。答案、评分细则、其他考生成果不能出现在考生材料中。
- 固定实操材料应有可下载附件、明确输入、验收结果和同等难度；使用虚构/脱敏数据。附件总数、名称、内容、下载和权限逐项核验，不只放文字文件名。

## 精确归档

先回读知识空间名、父节点完整路径/标题/父子关系，向用户给出具体路径候选并确认。例如“某资产工程 / 人才培养 / 某考试（版本）”；不能把“放到资产工程”当成精确位置。

建议该考试节点下按实际需要放置：考生说明与材料、试卷与评分 Base、管理/评分说明、受限答案与报告目录。是否新建这些子节点取决于现有结构；优先复用，不机械增目录。答案与成绩不能因继承同一父目录而向所有考生开放。

写入前形成简短确认单：

| 项目 | 必须落定的内容 |
|---|---|
| 路由 | 项目、Profile、user、知识空间、父节点路径与 URL |
| 内容 | 来源采用/排除、题量题型、版本、工具和时限、材料 |
| 结构 | 各表用途、考生身份与评分对象身份、字段映射和关联方式 |
| 分数 | 各模块原始/折合满分、附加分、舍入、待评状态、重复记录处理；多人评分的人员/角色/权重、AI与人工分工、齐套条件 |
| 权限 | 群名、群主/管理员、考生/评委范围、表单填写者、成绩与答案可见范围 |
| 流程 | 实时成绩记录创建方式、提交后页面与精确跳转 URL、通知对象、阅卷入口 |
| 验收 | 隔离测试数据/账号、允许的测试写入与清理、未支持配置的人工配合 |

确认已覆盖的事项不再二次索要授权；范围发生实质变化才重新确认。只要求制作 Skill 的任务不进入线上实施。
