# 表单、发布与考场权限

## 考生表单验收目标

每张考生试卷表必须有可用答题 Form，不能只给 Base 链接。界面采用清晰浅蓝风格（项目品牌可覆盖），题号作标题，完整题干/级别/分值/材料链接作说明，选择项纵向，必填状态醒目，**一页一题**。

实操题若有“成果链接＋附件”两个控件，优先作为同一逻辑题的同一页；先核验当前飞书是否支持页内组合。若只支持一控件一页，不能把 30 个控件谎称 15 个题页：报告限制、给可行结构并请用户决定。必要的身份/开场说明不冒充考试题。

| 设置 | 默认目标 | 验收说明 |
|---|---|---|
| 停止收集 | 正式开考时关闭 | 新表单在验收前保持未发布/停止收集；验收放行后才启用 |
| 匿名填写 | 关闭 | 不可代替登录实名关联 |
| AI 语音录入 | 开启 | 不代表允许使用 AI 代答，考试工具规则单列 |
| 谁可填写 | 仅邀请的人 | 不改为组织内任何人/互联网公开以绕开权限 |
| 登录验证 | 开启 | 非管理员实际验证 |
| 填写有效期 | 关闭 | 用户指定考试窗口时才覆盖 |
| 每用户提交次数 | 每天 1 次 | 每名考生、每张候选人答题表单；时区 GMT+08:00，其他时区须明确 |
| 总提交数限制 | 关闭 | 不用总数冒充个人次数 |
| 提交后通知 | 开启 | 默认当次经核验的组织者；不硬编码历史姓名 |
| 定时填写通知 | 关闭 | 不额外建定时任务 |
| 提交后修改 | 关闭 | 不允许考后悄改答卷 |
| 提交结果页 | 沿用当前形式 | 实际读取文字/按钮，不从截图“已编辑”猜正文 |
| 提交后跳转 | 开启并保持当前流程 | 必须获取完整真实 URL 并逐跳核验；截图前缀不足 |
| 抽奖 | 关闭 | 不配置无关玩法 |

新考试无“当前流程”时，提出与其模块匹配的最小流程让用户确认：例如“客观卷 → 实操提交 → 提交完成/成绩查询”。结果页不得提前显示标准答案、其他考生成绩或未完成的最终分。成绩记录如何产生必须有可执行的已确认方式；无现成自动化时，可由组织者/阅卷 Skill 幂等建立人员成绩行，不能让用户误以为跨表公式会自动生成新行。

发布是独立阶段门：新表单不能仅靠“暂不发送链接”阻止访问，应保持未发布或停止收集，并在受控验收时仅邀请已授权测试人员。复用已有群/表单可能已有真实考生，不能默停正在进行的考试；先核验活跃状态，确认维护窗口或采用独立新版本。配置和权限验收完成、测试数据处理完毕后，按已确认开考计划切至表中正式默认并回读；不提前把真实考生加入可填写范围。

评委/带教表：同样采用清晰题序和所需分页；只邀请已确认的评委群或人员。评分对象人员字段必填、评分人由系统记录。评委可能一天评多人，不默认套用考生每天一份；通过有效评分键去重并按合同约束重复评分。

## 三层权限分别完成

1. **群成员**：考场群成员表示允许参与考试的身份集合。
2. **表单填写者**：把该真实群作为对应表单的邀请对象，并保持仅邀请/登录。仅创建群不会自动获得表单权限。
3. **Base 数据与角色**：考生只需答题，默认不授予底层表编辑/答案/全体成绩权限。评委仅访问其职责所需表/记录；管理者/阅卷人获得经确认范围。仅把群加进 Base 不等于邀请表单。

同一群被用于候选答卷和评委打分会混淆权限时，拆出明确的评委/导师群或复用唯一已确认的现有群；具体命名由项目约定，不冒用不存在的“董事会”“考试评委”角色。

## 考场群幂等创建

- 用当前 user 身份检索精确群名 `[权限] - 考场 - {考试名称}`，并核验群主、描述、考试链接与租户。0 个则在已批准的新建考试范围内自动创建私有群，群主默认当前组织者；1 个且确属同考试则复用；多个/同名不同考试先确认。
- 群名超过当前平台长度限制时，不静默截断；向用户确认可区分的考试简称。版本是否进入考试名称应在合同内确定，避免跨版本权限串用。
- 描述注明只承载考试资格、不授予底层编辑权，提供受限管理入口；不放标准答案、成绩名单或敏感信息。仅加入明确给出的管理员/考生；创建空群可先交付入场教学。
- 读取当前群管理选项，尽可能限定邀请/分享由管理员控制；不开放任意人靠二维码加入即自动获得考试资格。平台的入群审批与表单白名单分别验收。
- 按 `lark-im +chat-create` 当前文档执行，优先 user 创建能力；不能用 bot-only API失败后切 bot创建。超时先查群再重试，不重复创建。

## API 与 UI 完成路径

先按能力路由尝试已文档化 API。当前快捷命令未暴露的分页、主题、每日限制、通知、结果页/跳转、具体邀请群等，继续查官方 OpenAPI；没有可用接口时使用已登录且身份可核验的浏览器 UI。浏览器操作前读对应 computer-use Skill。

逐项打开真实设置控件，读取当前值，修改，保存，重新打开回读。截图或结构化 UI 证据注明时间、表单和页面。不能通过猜内部接口、浏览器私有状态或自行截取凭据绕过能力限制。

UI 不可用、用户需登录或权限不足时，交付精确页面链接、点击路径、期望值、用户完成后回读方式；状态保持“待配置/待验证”。不得降级为公开权限，也不得用一张旧截图声称新表单配置完成。

## 必教：加入与移出考场

**加入**：打开指定考场群 → 管理员添加已核验飞书账号（或审批入群）→ 回读成员 → 用该考生账号打开答题链接 → 验证可填写、不可看答案和他人成绩。若要通知发卷，只向已授权的本场对象发送，不能自动向全公司广播。

**移出**：在考场群成员管理中移除明确指定账号 → 回读已不在群 → 检查该账号是否被直接邀请、通过其他邀请群或 Base 角色继续拥有权限 → 对本考试相关冗余授权按批准范围移除 → 原链接以该非管理员账号再次打开应拒绝新的填写。不得假设退群会撤销所有路径，不删除其历史答卷。已有会话/草稿、继承权限无法独立验证时明确残余风险。

交付时让用户实际演练或复述上述两条路径，注明管理者权限要求、目标群名/链接、考生表单入口及如何确认撤权成功。拥有者账号永远不能代替考生权限测试。
