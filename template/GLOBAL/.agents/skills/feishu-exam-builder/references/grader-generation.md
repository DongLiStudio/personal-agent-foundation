# 生成考试专属阅卷 Skill

## 何时生成

含实操题必须生成；含动态题、主观题或其他人工评分也应生成或适配已有版本。纯客观卷可不生成。生成 Skill 是该次建卷交付的一部分，不另问用户是否需要；但不能借此任命长期岗位或创建新会话。

名称示例 `<project>-<exam-slug>-<version>-grader`（小写、连字符、少于64字符）。放目标项目 `.agents/skills/`，不把考试资源 ID、考生信息写入 GLOBAL 通用 Skill。复用已有同版本 Skill 时先比对合同，不能覆盖他人改动。使用 `skill-creator` 校验入口与元数据。

## 必须实例化的内容

从 `assets/grader-SKILL.template.md` 生成主入口，并创建以下真实资源，不交付未替换变量：

- `references/routing.md`：项目、唯一 Profile/user、考试名称/版本、题库与资料链接、space/parent/base/table/form ID、成绩被评人字段、记录定位策略、逐题稳定 field ID、报告归档父节点、允许回写字段 ID/类型、只读公式字段。
- `references/rubric.md`：全量题目与评分点来源、原始与折合满分、受限答案文件/manifest路径、动态资料时点、补充材料和分歧处理、证据不足规则。不可只说“参考上次”。
- `references/report-template.md`：考试与考生标识、版本/提交时点、全部题干与选项、考生答案、标准答案/评分点、逐题得分与理由、每项链接和附件检查、公式差异、模块原始与折合总分、待确认项、建议与证据边界、允许字段写回记录。
- 必要的离线 manifest/计分工具可随项目 Skill 保留，若引用全局工具须明确依赖与版本；分发给他人时要能找到全部必需文件，不依赖本机临时路径。

多评委考试必须额外写明：该 Skill 是“只汇总人工评分”“提出待评委确认的建议”还是“获授权评其中某个模块”；AI 分不自动成为任一人工评委的分数。列出每个模块的评分责任人/角色、必需人数、权重、记录归属、去重键、齐套条件与最终状态门槛。未明确时只能只读检查和提出建议，不写两位人工评委的评分记录，也不替代缺席评委。某模块已评完不等于全场已完成。

## 阅卷不可变规则

1. 每次先读项目上下文并核验实际 Profile/user，再回读题库、版本、schema与考生记录。姓名不唯一时请求用户选择；按稳定用户 ID 和明确记录 ID 定位，不靠显示名合并。
2. 全量检查 manifest↔field ID/列名↔Form映射；有错位先停并上报，不把系统错误归责考生。
3. 从真实答卷独立计算客观题，与飞书公式逐题/分类/总分核对。任何差异直接报告、记录题号及预期/实际，不改公式，不用主观分补偿，不悄改最终分；需要授权人裁决。
4. 实操与附加题逐题进入**每个**提交链接、读取**每个**附件和成果内容。维护访问状态、证据对应评分点、版本/时间、授予阅卷身份的权限；权限失败或不可解析是待核，不等于答错。未知附件代码不执行，必要运行须隔离且另有授权。
5. 人工分严格按该题 rubric，单项分不越界；真实零分保存为0，待核/未评为空/状态明确。动态题用提交时点官方一手来源。发现答案等价但公式未覆盖也上报，不自扩词库。
6. 唯一报告键为“考试＋版本＋考生稳定ID＋有效答卷record ID”；查到1份更新原报告，0份新建，多份停并询问。报告含全部题目（含未答/0分），不得只列错题或摘要。
7. 只写当前白名单中明确归该 Skill 负责的人工分、评语、阅卷人、状态、报告链接；多评委分按已确认角色读取/汇总，不覆盖他人评分记录。不改答卷、题库、公式、结构、自动化和权限。若成绩行尚不存在，只能按建卷合同明确授权的幂等建行规则创建；没有该规则时报告缺行。
8. 报告与成绩写后独立回读，机械校验小计/总计/折合分及链接。差异、缺证据未解决不得标最终完成。外部决策保持人工边界。

## 必须教用户的调用

交付**实际名称**和可复制指令，例如：

> 使用 $project-example-v1-grader 批阅《实际考试名》1.0 的张某；如重名请先让我确认账号或答卷记录。逐项核验所有成果，公式差异直接上报，写回允许字段并回读报告。

讲清：考生完成全部阶段后运行；在哪里找到候选答卷/用户标识；被挡权限时如何授予仅阅卷所需访问；看到“待核/待裁决”不能当最终成绩；报告与成绩位置；再次运行更新同一报告而非重复创建。不能只说“以后让 AI 批改”。
