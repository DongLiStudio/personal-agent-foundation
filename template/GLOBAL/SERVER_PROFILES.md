# 服务器 Profile

本文件登记跨项目复用的服务器连接路由、服务归属与安全边界。它不是密钥仓库、运行日志或项目部署文档。

## 管理原则

- 只登记需要跨项目路由的共享服务器；单项目、客户隔离或短期环境留在对应项目。
- 使用稳定逻辑 Profile 名称，不设置隐式默认服务器。
- 每项至少说明治理归属、环境、SSH 别名、允许的身份角色、主机指纹核验来源、服务归属和默认操作边界。
- 地址、账号权限、主机指纹、容器和服务状态可能变化；每次操作前实时核验。
- 不记录私钥正文、密码、API Key、App Secret、Access Token、Cookie、配对码或会话票据。

## Profile 登记

当前未登记服务器。需要连接服务器时，由用户确认 Profile 与目标服务，再通过安全渠道恢复本机身份文件，并从可信渠道核验主机指纹。

建议结构：

```text
## Profile：<稳定逻辑名称>
- 治理归属：<用户、组织或项目>
- 环境：<生产、预发布或测试>
- SSH 别名：<本机 ssh config 中的稳定别名>
- SSH 主体：<最小权限账号>
- 主机指纹核验：<可信云控制台或既有已验证会话>
- 服务索引：<服务名、租户/项目、部署入口、持久化和网络边界>
- 默认操作边界：<只读、可部署或需逐次授权>
```

## 恢复与连接

1. 通过安全渠道把私钥恢复到用户本机密钥目录；不经 GLOBAL、项目 Git 或聊天传输。
2. 按登记事实重建本机 SSH config，但不要自动接受未知或变化的主机密钥。
3. 从可信渠道核验主机指纹，再以 `BatchMode` 检查身份。
4. 只读核对目标服务、租户、目录、端口和运行状态；有歧义时停止写操作。
5. 发布、重启、改网、改卷、改权限或读取 Secret 必须符合当前项目规则和用户授权。
