# 服务器 Profile

本文件登记跨项目复用的服务器连接路由、服务归属与安全边界。它不是密钥仓库、运行日志或项目部署文档。

## 管理原则

- 登记需要跨项目或跨会话稳定路由的用户受管服务器。项目专属部署步骤和运行资料仍留在对应项目；短期测试环境不进入本索引。
- 使用稳定逻辑 Profile 名称，不设置隐式默认服务器。
- 每项至少说明治理归属、环境、SSH 别名、允许的身份角色、主机指纹核验来源、服务归属和默认操作边界。
- 地址、账号权限、主机指纹、容器和服务状态可能变化；每次操作前实时核验。
- 不记录私钥正文、密码、API Key、App Secret、Access Token、Cookie、配对码或会话票据。
- 详情只保存现行路由、安全边界、服务索引和恢复所需信息；移除已撤销人工身份指纹及重复迁移/验收流水，过程留项目任务文档与 Git 历史。保留有效自动化身份、必要回退路径和未解决风险，不用历史健康快照代替实时检查。

## Profile 登记

当前未登记服务器。需要连接服务器时，由用户确认 Profile 与目标服务，再按下方 Bitwarden SSH Agent 规则建立人工身份，并从可信渠道核验主机指纹。

每个已登记 Profile 的详情应放在 `servers/<profile>.md`；本文件只保存索引和读取路由，不默认展开全部服务器详情。

建议结构：

```text
## Profile：<稳定逻辑名称>
- 治理归属：<用户、组织或项目>
- 环境：<生产、预发布或测试>
- 地址与端口：<经确认的域名/IP与SSH端口>
- SSH 别名：<可选的本机 ssh config 稳定别名>
- SSH 主体：<经用户确认的账号>
- 当前人工 SSH 身份：Bitwarden Agent；<实际接入方式与验收日期>
- 客户端公钥指纹：<公开指纹>
- 主机指纹核验：<可信云控制台或既有已验证会话>
- 服务索引：<服务名、租户/项目、部署入口、持久化和网络边界>
- 默认操作边界：<只读、可部署或需逐次授权>
- 详情：`servers/<profile>.md`
```

## 共通操作流程

1. 人工 SSH 默认使用 Bitwarden 桌面端 SSH Agent：检查 Agent 可用、目标公钥指纹及本次授权，不以本机私钥文件存在作为前提。
2. 验证主机指纹、SSH 主体和实时权限；发现不一致立即停止。
3. 只读确认目标服务的工作目录、容器、端口、挂载和健康状态。
4. 仅在当前授权范围内执行变更，并回读服务状态、日志摘要和外部验收结果。
5. 更新项目专属部署文档；只有跨项目路由、归属或稳定安全边界变化时才更新服务器详情。

## 共通迁移与恢复

换电脑、迁移 Agent 根目录或更换 SSH 身份时：

1. 安装并解锁 Bitwarden 桌面端、启用 SSH Agent，默认每次签名提示授权；目标密钥在 Bitwarden 内生成和保管，不导出私钥到本机磁盘。
2. 从目标服务器详情读取地址、端口、主体、客户端公钥指纹和主机指纹；别名只是可选路由，不是必需凭据。
3. 从可信渠道复核主机指纹，再按详情文件重建本机 SSH config。
4. 使用新的 Agent 连接验证 `whoami`，并只读核对目标服务器的服务索引。
5. 将发生变化的项目专属路径写回对应项目；不要把 Secret 或易变运行日志迁入 GLOBAL。

## 任务内 SSH 会话

- 同一任务、同一服务器、同一主体的连续检查与实施默认复用一个持续 SSH 会话，批量执行必要命令，避免逐条重新连接和反复申请 Bitwarden 签名。
- 建连前说明目标 Profile、主体和操作范围；首次连接或密钥轮换验收使用独立新连接。连接断开、目标或主体改变时重新认证，不把旧授权扩大到其他任务。
- 保留主机指纹校验和 `ForwardAgent no`；保持 Bitwarden 签名授权为始终提示，不为减少弹窗改成从不提示或长期记住授权。
- 已认证会话后续命令不会逐条请求签名；锁定 Bitwarden 不会终止已有会话。完成、取消或等待用户决策时退出；不默认建立跨任务常驻连接或持久复用 socket。
- 进程名称只能帮助辨认，不能作为可信身份或防仿冒证据。使用已核验来源的 SSH 客户端和明确路径；结合可用的数字签名/哈希、实际请求时机、父进程及目标身份核验。

## 人工 SSH 身份规范

- 人工登录及人工建立的 SSH 隧道统一优先使用 Bitwarden Agent。没有桌面端时引导安装、启用和验证；`bw` CLI 不是桌面 SSH Agent 的替代品。不默认执行 `ssh-keygen` 创建磁盘私钥，也不从密码库导出私钥。
- 新身份默认在 Bitwarden 创建独立 Ed25519 SSH 密钥条目，记录目标、账号、端口和公钥指纹；服务端只安装公钥。用户指定 root 时据实登记，不能擅自另创账号或替换其登录主体。
- Windows 核验实际使用的 OpenSSH 客户端及 Agent 接入；macOS 按 Bitwarden 安装来源配置 `SSH_AUTH_SOCK`，终端持久配置与 GUI 客户端接入分别验收。Git、WindTerm 等不能仅凭安装 Bitwarden 就认定接入成功。
- 验收时禁用文件身份、密码回退及连接复用，确认真正由 Agent 完成新的认证。多把 Agent 密钥可能耗尽 `MaxAuthTries`；公开公钥选择器可按需使用，但不强制保存、不冒充私钥，也不能从服务器主机公钥推导用户身份。
- 保留主机指纹校验；不默认转发 Agent。授权拒绝或 Agent 锁定先处理客户端，不放宽服务器认证，不静默增加认证次数。
- 轮换先追加新公钥、独立连接验收并核对恢复入口；仅在明确授权后精确撤销旧公钥。禁用密码必须另有授权，并检查有效 Include/Match 配置和负向连接。
- 本地文件私钥仅为用户在明确理解泄露风险后仍坚持的例外：再次确认具体目标与必要性，优先加密口令、最小 ACL，并记录例外范围和验收；不能因 Agent 暂时失败而自动回退。
- Agent 减少可直接复制的私钥文件和无提示签名风险，不抵御所有终端木马、已授权会话劫持或误批准；不得承诺绝对安全。
