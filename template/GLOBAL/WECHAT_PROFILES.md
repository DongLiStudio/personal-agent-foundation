# WeChat Profiles

本文件记录本机微信只读分析的非敏感逻辑身份路由。真实 `db_storage` 路径与经数据库页校验的密钥目录由当前 Windows 用户的 DPAPI CurrentUser 加密保存在宿主凭据槽中，不进入 GLOBAL、Git、日志或报告。

## Profile 索引

| Profile | 主体描述 | 用途/租户 | 项目路由 | 当前宿主状态 | 最近核验 |
| --- | --- | --- | --- | --- | --- |
| `个人微信` | 用户本人当前使用的个人微信 | 个人 | 按任务选择 | `可用（支持离线读取）` | `2026-09-30` |

## 路由规则

- 不设置全局默认 Profile；每次发现、连接、查询、搜索、统计或总结都显式指定逻辑 Profile。
- “租户”指用户授权的本地微信数据身份。一个 Profile 只绑定一个宿主候选；同一逻辑身份换电脑后必须重新发现、确认和绑定。
- 项目可以声明推荐 Profile，但不得绕过当前任务的明确选择；名称相近、最近活跃或当前登录均不是自动选取依据。
- GLOBAL 只保存逻辑名称、非敏感主体描述、用途、项目路由和验证状态；不保存 wxid、数据库路径、密钥、聊天内容、候选指纹或 DPAPI 密文。
- 用户确认账号归属并绑定 Profile，即授予该 Profile 在本机的持续只读权限；后续用户提出具体查询即可直接读取本机可用数据库并进入当前 Agent/模型上下文。首次取钥和明确需要的密钥刷新由包装器在已绑定授权范围内自动完成，不再逐次询问；新密钥必须与所选 Profile 已绑定数据库校验一致，无法确认运行账号身份时停止并告知用户，普通查询错误不得误判为需刷新。
- 删除或重命名 Profile 前，先搜索项目引用；删除本机绑定会撤销持续只读授权并删除 DPAPI 凭据槽，但不得删除微信数据。

## 换机恢复

1. 从 GLOBAL 恢复并安装 `wechat-readonly-analyst`。
2. 在用户级安装副本运行 `scripts/install.ps1` 和 `profile_manager.py self-test`。
3. 逐个运行 `discover`，让用户依据当前登录身份和活动时间确认候选；不得复制旧电脑的 DPAPI 槽。
4. 对每个 Profile 执行 `connect --confirm-owner`，再直接用最多 3 条会话完成自动取钥与最小回读。
5. 只有 `available`、`offline_key_available` 与回读都成功后，才把状态标记为 `可用（支持离线读取）`。
